## Статусы и приоритет документов

«Принято для проектирования» — решение, которое следует реализовывать при соответствующем поручении. «Предложено» — вариант с указанным gate перед реализацией. «Открыто» — недостающая проверка с владельцем и сроком относительно этапа. «Реализовано» допустимо только со ссылкой на код и проверку.

При противоречии сначала учитывай актуальное поручение пользователя. Затем нормативный контракт соответствующего раздела и ADR; README — обзор, baseline — исторический снимок. Не выбирай удобную интерпретацию молча: исправь противоречие в документации в рамках задачи. В этой редакции новые спецификации заменяют прежние краткие ARCHITECTURE/ROUTING/PROTOCOLS/ROADMAP.

## Первый шаг следующего агента

Проверить актуальный HEAD и выполнить T00 из roadmap: выбрать проверяемую точную сборку sing-box и подтвердить native Android bridge, Linux TUN ownership и семантику logical rules. Не начинать массовое построение экранов до рабочего сетевого среза. Реализацию начинать только по поручению пользователя.
