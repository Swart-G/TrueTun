# TrueTun: инструкции для ИИ-агентов

## Обязательный контекст

TrueTun — Flutter-клиент для Android и Linux. Приоритет: надёжное VLESS-подключение, подписки, упорядоченная маршрутизация, Android include/exclude и локальные объяснимые рекомендации приложений. Hiddify служит архитектурным ориентиром; Mihomo — ориентиром для редактора правил. Это не требование копировать их код или поддерживать любой их конфиг без потерь.

1. Прочитай [карту документации](docs/README.md), [состояние репозитория](docs/architecture/01-baseline.md), [архитектуру](docs/ARCHITECTURE.md).
2. Перед изменением соответствующего модуля прочитай его спецификацию и [контракты](docs/architecture/03-contracts.md).
3. Выбери конкретную задачу из [плана](docs/ROADMAP.md) и следуй [процессу работы](docs/agents/WORKFLOW.md).
4. Сопоставь план с текущим кодом: baseline зафиксирован на конкретном коммите и может устареть.

## Текущая граница работы

Этот пакет подготовлен как документация архитектуры, без реализации приложения. Само наличие плана не разрешает начинать реализацию. Если последующее поручение пользователя явно требует реализации, выполняй порученный этап без повторного запроса разрешения. Не превращай узкую задачу в реализацию всей дорожной карты.

## Неподвижные инварианты

- Domain не импортирует Flutter, платформенные каналы, файловую систему, HTTP-клиент или формат sing-box. Зависимости направлены внутрь; композиция — в app/bootstrap.
- UI вызывает application use cases. Ни виджет, ни repository не запускают ядро и не меняют системные маршруты.
- Одна активная VPN-сессия и один авторитетный supervisor на устройство/пользовательскую сессию. Flutter UI не является владельцем Android VPN.
- В persistent models хранятся стабильные IDs и ссылки на секреты, а не outbound tags, plaintext credentials или готовый runtime JSON.
- Компилятор детерминирован, не делает I/O и не загружает rule sets. Используй неизменяемый snapshot.
- Неподдерживаемое поле нельзя молча удалять. Успешный импорт не означает возможность подключения.
- Native app filter определяет вход в VPN, route rule — действие внутри VPN. Не путай bypass с DIRECT внутри туннеля.
- Пустой effective Android include-list — ошибка, никогда не вызов Builder без allowed apps.
- Порядок правил сохраняется; платформенный matcher не исчезает при переносе; final action задаётся отдельно.
- Запуск процесса не равен готовности VPN; откат — новая попытка старого плана, а не гарантия сохранения TCP-сессий.
- Секреты и содержимое пакетов не попадают в журналы, screenshots, fixtures, PR и диагностические архивы.
- GUI Linux не работает от root. Privileged helper не принимает произвольные shell-команды, executable paths или конфиги ядра.
- Не ослабляй TLS, правила и режим блокировки трафика для того, чтобы тест стал зелёным.

## Изменения и проверки

Сначала объясни текущий пробел и перечисли затрагиваемые контракты. Делай минимальный вертикальный срез. Для изменения семантики обнови ADR, спецификацию, миграцию (если нужна) и поведенческие тесты вместе. Не объявляй native/API интеграцию существующей по одному примеру из документации upstream.

Текущие проверки проекта: `flutter pub get`, `flutter analyze`, `flutter test`; форматирование проверяй `dart format --output=none --set-exit-if-changed lib test`. Не выполняй bootstrap или formatter при задаче только на документацию. Если инструмент недоступен, укажи «не запускалось» и причину. Не выдумывай результаты CI, реального устройства, сервера или packet capture.

Перед PR проверь diff: посторонние файлы, секреты, изменения схемы, зависимости, сломанные ссылки. Отчёт: что изменено, что проверено, что осталось, следующий ограниченный шаг. Не публикуй релиз и не меняй лицензию в рамках обычной разработки без соответствующего поручения.

Язык документации — русский; идентификаторы и имена файлов — английские. Новую зависимость обоснуй конкретной задачей и зафиксируй версию при внедрении. Параллельная работа агентов допустима только если отдельно поручена; роли в workflow — зоны ответственности, а не команда автоматически создавать субагентов.
